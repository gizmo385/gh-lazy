| `searchable-tables.search` | `/` reveals a "Search..." input above the table; Enter filters rows by case-insensitive substring over the row's cell text; empty query restores all rows; focus returns to the table | `ui/widgets/common.py` `SearchableDataTable.action_focus_search`, `handle_submitted_search` | M1 | in progress | #78, #101 | Filter is applied on submit, not per keystroke. Rust (#101): `components/table/search.rs`; the text matched is Python's `str()` of the row tuple (`py_repr.rs`, pinned by Python-generated golden cases), so queries match quotes, commas and across cells (`', 'gh`). Submitting reinserts every item in `items` order, so ties reset, and the cursor and scroll go to 0. Rows inserted later show even when they don't match. The box is a single-line `components/text_input.rs` with Textual's `Input` editing keys. Focusing it (`/`, Shift+Tab, a click before the click places the cursor) selects all its text, as Textual's `select_on_focus` does, so typing replaces the last query. The selection keys (`shift+arrows`, `ctrl+shift+a`) and the clipboard keys (`ctrl+x`/`ctrl+c`/`ctrl+v`) aren't handled yet: they come with the M3 shared input. The cursor doesn't blink (Textual blinks it every 0.5 s while focused, whatever the animation level); before this row can go to `parity` that needs either a blink or a proposed `intentional diff` (`status: needs-decision`). |
