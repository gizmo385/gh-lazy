# Terminal caveats

Part of the [parity matrix](../README.md), which defines the columns, the status values and how to edit
this file.

| Id | Caveat | Affects | Recommendation |
| --- | --- | --- | --- |
| `terminal-caveats.ctrl-m-enter` | `ctrl+m` and Enter are the same byte (CR) without the kitty keyboard protocol. | `pull_request.merge` | Keep the id and default. Only treat a disambiguated `ctrl+m` as merge; never Enter. See Py bug B30. Implemented in #262 (`pr-merge` sends CSI 109;5 u). |
| `terminal-caveats.shift-enter` | `shift+enter` arrives as plain Enter in legacy terminals. | `modal.submit` | Push kitty enhancement flags when supported; keep the Submit buttons working; don't map plain Enter to submit inside multi-line editors. |
| `terminal-caveats.ctrl-v-paste` | `ctrl+v` is often captured by the terminal as paste. | `link.paste` | Decided (#197): a bracketed paste on the main screen opens the paste link modal prefilled with the pasted text; see `markdown-links.paste-opens-link-modal`. |
| `terminal-caveats.uppercase-bindings` | Uppercase bindings (`M`, `I`, `P`, `E`, `O`, `J`, `K`, `G`, `R`, `T`, `F`) arrive as shifted characters; some terminals report `shift+m`. | all uppercase ids | Normalize `shift+<letter>` and `<LETTER>` to the same key. |
| `terminal-caveats.punctuation-key-names` | Punctuation keys are saved by the Python Settings modal as Textual names (`question_mark`, `slash`, `dollar_sign`, `circumflex_accent`, …). | `bindings.overrides` | Keymap parser accepts Textual key names and literal characters (#73). |
| `terminal-caveats.key-capture` | A Key Bindings row records the key the terminal reports. Without the kitty protocol `ctrl+m`, `ctrl+i` and `ctrl+[` arrive as `enter`, `tab` (which moves focus on) and `escape` (which resets the row), and `shift+enter` as `enter`, as Textual sees them too. | Settings Key Bindings tab (#194) | Record what crossterm reports, written as Textual's name; no extra hint (Python shows none; Chris, 2026-10-28, on #194). `tab`, `shift+tab` and `escape` can't be bound from the tab. |
| `terminal-caveats.escape-ambiguity` | `escape` is ambiguous with Alt-prefixed sequences; crossterm handles the timeout. | `modal.close`, maximize restore, link hints | No action beyond crossterm defaults. |
| `terminal-caveats.q-in-inputs` | `q` closes modals and quits the app, but must type a `q` inside text inputs. | `app.quit`, `modal.close` | Text inputs get first refusal on printable keys. |
| `terminal-caveats.footer-key-labels` | Footer key labels: Textual shows `^p` for `ctrl+p`. | footer, help panel | decided: Textual notation (`^p`) |
| `terminal-caveats.dim-text` | Textual draws `dim` (Rich `[dim]`, `style="dim"`, TCSS `text-style: dim`) as SGR 2 only on the ANSI themes; elsewhere its `ANSIToTruecolor` filter replaces it with the cell's fg blended 66% from the cell's bg. | every dim text | `Modifier::DIM` means Textual's dim; `Theme::resolve_dim` at the end of `App::render` blends it on non-ANSI themes (#363). `text-opacity` / `opacity` never produce SGR 2. |
| `terminal-caveats.terminal-hyperlinks` | Terminal hyperlinks (`[link=…]`) are used for a few links (run number, profile login); others are in-app links. | Run Overview, User profile | Render as OSC 8 where supported; treat as hint targets only if the spec says so. Rust (#356): `hyperlink.rs` writes OSC 8 for the run Overview's `(#N)` and the profile's `@login`, after each frame and beside ratatui's buffer (views record them into `RenderCx::hyperlinks`; cells drawn over afterwards, by a dialog, its dim or a toast, aren't linked). Not written when `TERM` is `linux` or `dumb`; URLs outside printable ASCII aren't linked. Snapshots and `TestBackend` never see the escapes; the structural check can't see links, so unit tests cover them. Checked (2026-10-30, 9446515): the `run-details` and `user-profile` PTY output (`pty.raw`) has the same OSC 8 links as Python's, on the same cells and to the same URLs (`ESC \` terminated; Rust's ids are shorter hex, which terminals only use to group cells). |
| `terminal-caveats.emoji-zwj-width` | Terminals disagree on the width of an emoji ZWJ sequence (`👨‍👩‍👧`): Rich and `unicode-width` count two cells, many terminals (and the harness's `vt100` parser) one or two per joined emoji. Zero-width characters are written by Textual and dropped by ratatui, so their cells differ though they look the same. | tables, bodies, diffs, logs (#327) | Lay out by grapheme as ratatui does (two cells); keep ZWJ sequences and zero-width characters out of cross-app scenarios and cover them with unit tests. |
