# B100: Two-letter link hint labels can't be typed

- Id: B100
- Status: open
- Answer:
- Python reference: `ui/widgets/link_hints.py` `_hint_codes`, `LinkHintScreen.on_key`
- Recommendation: When more than 26 links get labels, give every one two letters (`aa`, `as`, `ad`, …, first letter
  major), so no label is the start of another and every link can be picked. At most 676 links get labels (#340).
- Rows: `markdown-links.hint-labels`

`_hint_codes` returns the 26 letters of `asdfghjklqwertyuiopzxcvbnm` for the first 26 links and two-letter codes
(`aa`, `as`, …) for the rest. `LinkHintScreen.on_key` follows a link as soon as the typed letters equal a code. Every
two-letter code starts with a letter that is itself a one-letter code, so typing its first letter follows that other
link at once: with more than 26 links, links 27 onward have labels that can't be reached. Their labels are shown
(every label is padded to two cells wide), and seen under the parity harness (#196's design probe: "Item 26: see
asc26", where `as` covers "do").

The issue outline (#196) already describes the intended behavior as "two letters each when there are more than 26
links". A Vimium-style mixed scheme (one letter for as many links as fit, two letters under the remaining first
letters) would also work but labels differently from both.
