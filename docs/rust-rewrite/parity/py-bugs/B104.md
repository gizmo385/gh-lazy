# B104: The paste link modal queues its keys while a link resolves, then applies them

- Id: B104
- Status: answered
- Answer: Follow the recommendation. ([Chris, 2026-10-30](https://github.com/gizmo385/gh-lazy/issues/197#issuecomment-6532915561))
- Python reference: `ui/screens/link_paste.py` `PasteLinkModal._parse_link_and_action`, `action_submit`,
  `action_close`; Textual `MessagePump` (one message at a time per screen), `Widget.watch_disabled`
- Recommendation: Do as the lookup dialogs do (B51, [lookup-cancel-in-flight](../decisions/lookup-cancel-in-flight.md)),
  but keep what Python draws: Open and Cancel are disabled while the link resolves (and Open, if it was focused, loses
  focus), the dialog otherwise stays responsive, `modal.close` closes it at once, cancels the request in flight and
  drops a late answer, so nothing opens; a second submit while one is in flight is ignored; typing and focus moves
  work as usual.
- Rows: `modals.paste-link-in-flight`

`_parse_link_and_action` disables Open and Cancel, then awaits up to three GitHub requests (the repo, then the issue,
then the pull request, or the user) inside the screen's message handler. Textual handles a screen's messages one at a
time, so while they're out every key that reaches the dialog (escape, `q` outside the input, tab, typing) waits in its
queue. When the answer comes back the dialog either closes with the subject, which then opens, or toasts; only then
do the queued keys run, and after a close they run against the main screen.

A Python-only probe with the repo lookup answered after 3 s (`ctrl+v`, type a link, tab, enter, escape after 0.6 s;
not committed) showed Open and Cancel dimmed and the dialog still up 0.4 s after escape, then error /
"GitHub lookup failed" "Could not resolve link!", then the dialog closed by the queued escape. With a link that
resolves, the escape would have landed on the main screen after the subject opened.

So a user who presses escape because the lookup is slow can't cancel it, as with the lookup dialogs (B51).

Found while designing the paste link modal (#197).
