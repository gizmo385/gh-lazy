# B110: Browsing other repos with preload on logs an error for each one

- Id: B110
- Status: open
- Answer:
- Python reference: `ui/screens/primary.py` `SelectionsPane.load_repository`; `lib/github/pull_requests.py` `list_pull_requests_for_commit`; `lib/context.py` `current_local_commit`
- Recommendation: Keep looking the commit up in every selected repo, since a fork's commit can be found in the repo its pull request targets, but treat a 422 (GitHub's "No commit found for SHA") as no pull requests, logged at debug. Any other failure still logs ERROR `Error loading PRs for current commit`.
- Rows: `pull-requests.preload-lookup-error`

With `pull_requests.preload_pull_request_for_current_commit` on, `load_repository` looks up the working directory's
HEAD commit in whichever repo is selected; it never checks that the selected repo is the working directory's. The
only guard is that the working directory's branch isn't the *selected* repo's default branch. For a repo the commit
isn't in, GitHub answers 422 "No commit found for SHA", and `list_pull_requests_for_commit` logs it with
`lg.exception`, so every repo the user browses adds an ERROR `Error loading PRs for current commit` line to the
command log (and a traceback to the log file), and spends one API call. Reproduced under the parity harness (#198,
scenario `pr-preload-skip`, capture `other-repo`).

Skipping the lookup outside the working directory's repo would silence it, but would also lose the case where it
helps most: a contributor working in a clone of their fork, browsing the upstream repo their pull request targets.
So the recommendation keeps the lookup and only quiets the expected "not in this repo" answer.
