# B120: The Jobs tab's success `✓` is uncolored

- Id: B120
- Status: answered
- Answer: Don't copy it; keep `✓` greenyellow, and match Python's ANSI red, yellow and cyan for `✗`, `○` and `⋯`.
  ([Chris, 2026-10-30](https://github.com/gizmo385/gh-lazy/issues/365))
- Python reference: `ui/widgets/workflow_run_details.py` `WorkflowRunJobsTabPane._format_job_status`,
  `_format_step_status`, used as `Tree` labels in `load_jobs`; Textual 8.2.5 `widgets/_tree.py`
  `Tree.process_label` (`Text.from_markup` for a `str`)
- Recommendation: Don't reproduce it. The Jobs tree's `✓` is greenyellow (`#adff2f`), as the Overview's is.
- Rows: `workflows.jobs-status-icons`

The Jobs tab labels each job and step with `[greenyellow]✓[/]`, `[red]✗[/]`, `[yellow]○[/]` or `[cyan]⋯[/]`
markup. Textual's `Tree` parses a `str` label with Rich's `Text.from_markup`, not Textual's own markup, so the
names are Rich color names. Rich has no `greenyellow` (its name is `green_yellow`): the style fails to parse and
the `✓` takes the tree row's own color (`#e0e0e0` on textual-dark, in the `run-details` scenario's `jobs`,
`job-expanded`, `step-logs` and `no-logs` captures). The others are Rich's standard colors 1, 3 and 6, which
Textual paints through its terminal theme: `#f4005f`, `#fd971f` and `#58d1eb` (MONOKAI) on dark themes,
`#aa3731`, `#cb9000` and `#0083b2` (ALABASTER) on light ones, and the terminal's own palette under the ANSI themes.

The Overview's job summary uses the same markup through Textual's `Content.from_markup`, where `greenyellow` is
`#adff2f`, so the same successful job is a green `✓` in the Overview and an uncolored one in the Jobs tab. The
author's intent is the green one. Rust draws the Jobs tree's `✗`, `○` and `⋯` in the ANSI colors, as Python does,
and keeps its `✓` greenyellow (#365).
