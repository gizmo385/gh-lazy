# B170: A screenshot that can't be saved says only "Failed to save screenshot"

- Id: B170
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-31, on #291)
- Python reference: Textual 8.2.5 `app.py` `App.deliver_screenshot`, `App._deliver_binary` (saves to platformdirs'
  `user_downloads_path()`), `App._on_delivery_failed`; `driver.py` `Driver.deliver_binary` (`save_file_thread`);
  platformdirs `unix.py` `Unix.user_downloads_dir`, `_get_user_dirs_folder`
- Recommendation: Save to the same directory, but name the path and the I/O error in the toast, as
  `toasts.settings-save-failed` does: error / "Screenshot", "Failed to save screenshot to '<path>': <I/O error>".
  Don't create the directory. An intentional diff on the failure toast only (#291).
- Rows: `command-palette.screenshot`

The palette's "Screenshot" writes an SVG to the Downloads directory: `XDG_DOWNLOAD_DIR` from
`$XDG_CONFIG_HOME/user-dirs.dirs` on Linux, otherwise `~/Downloads`. Textual doesn't create the directory, and when
the write fails for any reason (no `~/Downloads`, as on most servers and SSH hosts and in the parity harness's
isolated `HOME`, a read-only or full disk) the only feedback is an error toast titled "Screenshot" that says "Failed
to save screenshot". The path it tried and the reason go to Textual's devtools log, which a user doesn't see, so they
can't tell where it tried to write or what to fix. Seen with a scratch scenario against the Python app (2026-10-31):
with no `home/Downloads`, the toast is "Failed to save screenshot"; with one, it's "Saved screenshot to
'<home>/Downloads/LazyGithub_2026-11-01T05_20_25_627683.svg'".
