# B182: A reply to a reply in a review thread posts to the reply's id

- Id: B182
- Status: answered
- Answer: Follow the recommendation: post to the thread's first comment. (Chris, 2026-11-10, approved fixing #418 with
  the M5 close-out)
- Python reference: `lib/github/pull_requests.py` `reply_to_review_comment` (L117-123); `ui/screens/new_comment.py`
  `NewCommentContainer.post_comment`
- Recommendation: `r` on any comment of a review thread quotes that comment and posts through
  `POST /repos/{owner}/{repo}/pulls/{n}/comments/{comment_id}/replies` with the thread's first comment as
  `comment_id`, as the diff's thread reply (#385) does.
- Rows: `keybindings.conversation-comment-reply`

GitHub's docs for the replies endpoint say `comment_id` must be a top-level review comment: "Replies to replies are
not supported." Python posts to the id of the comment `r` was pressed on, so a reply to a reply asks GitHub for
something it doesn't support. The Rust app did the same until #418. The visible text doesn't change: the dialog
still quotes the comment `r` was pressed on.

Found while designing #385.
