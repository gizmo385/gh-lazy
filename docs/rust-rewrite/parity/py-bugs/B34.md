# B34: The command log sends ESC, DEL and other control characters to the terminal raw

- Id: B34
- Status: answered
- Answer: Follow the recommendation. ([Chris, 2026-10-30](https://github.com/gizmo385/gh-lazy/issues/317#issuecomment-6515229902))
- Python reference: `textual/widgets/_log.py` `Log._process_line` (Textual 8.2.5); `ui/widgets/command_log.py` `CommandLogLoggingHandler`, `LazyGithubCommandLog`
- Recommendation: replace every C0 control (U+0000–U+001F) and DEL (U+007F) with U+FFFD, as the Rust command log does. Line boundaries (`\n`, `\r`, VT, FF, FS, GS, RS) have already been split off by then, and tabs expanded.
- Rows: `main-layout.command-log`

Textual's `Log._process_line` replaces only `[\u0000-\u0014]` with `�`. After that, Rich's `Text` strips BEL, BS, VT,
FF and CR, but those are already `�` by then. Nothing else gets filtered, so ESC (U+001B), DEL (U+007F) and
U+0015–U+001A reach the terminal as they are:

- An ANSI sequence in a logged message is interpreted, not shown. `ESC[31m` turns the rest of the line red, and other
  sequences can move the cursor or clear parts of the screen. ANSI codes can get into a message through `gh` stderr
  or a pasted title.
- `cell_len` counts ESC as 0 cells, so the horizontal scroll extent is off as well.

**Question for Chris: C1 controls.** U+0080–U+009F, apart from U+0085 (NEL, a line boundary), pass through in both
apps. U+009B is the 8-bit CSI, so in a terminal that honours 8-bit controls it starts an escape sequence just as ESC
`[` does. Most UTF-8 terminals ignore C1 characters. Should Rust replace them with U+FFFD too? Recommendation: yes,
for the same reason as C0. Until you answer, Rust leaves them as Python does.
