# B35: Logging from the notifications thread worker can crash the app

- Id: B35
- Status: open
- Python reference: `ui/screens/primary.py` `refresh_notification_count` (`@work(thread=True)`), `ui/widgets/command_log.py` `CommandLogLoggingHandler`
- Recommendation: Don't reproduce. Rust logs from the event loop, and the line reaches the command log as an event.
- Rows: `main-layout.unread-refresh`, `main-layout.command-log`

`refresh_notification_count` runs in a thread worker. When `gh` is logged out it calls `lg.error(...)` there, and the
command log's logging handler writes the line into the Textual `Log` widget from that thread. `Log.write_line`
re-arranges the screen, which needs the `active_app` context variable that only the app's own thread has, so now
and then the app dies with `LookupError: <ContextVar name='active_app' ...>` (frames `_run_threaded` →
`refresh_notification_count` → `error` → `emit` → `write_line` → `arrange`). It depends on timing: the parity
scenario `toast-error-notifications` hit it once in about ten Python runs, with notifications enabled and `gh`
logged out. The same handler is reached from any other thread worker that logs.

Found while implementing #81. Until Chris answers, the recommendation stands.
