# B36: An overflowing status-bar half disappears instead of clipping

- Id: B36
- Status: answered
- Answer: Keep Rust's clip. (Chris, 2026-10-25, [comment on #71](https://github.com/gizmo385/gh-lazy/issues/71#issuecomment-6407803743); options in #148)
- Python reference: `ui/screens/primary.py` `LazyGithubStatusSummary`, `CurrentlySelectedRepo`, `UnreadNotifications`
- Recommendation: Clip the text at the edge of its half, as #143 does.
- Rows: `main-layout.status-summary`, `main-layout.status-current-repo`, `main-layout.status-unread`

Each half of the status summary is a one-row `Static`. When its text is wider than the half, Textual word-wraps it
onto a second row that the one-row box hides. So a long repo name disappears completely: at 100 columns, any name
over about 35 characters leaves only `Current repo:`. Below about 58 columns, the `50+` unread count goes the same
way. Rust clips the text at the half's edge instead (the `status_long_repo_clipped` snapshot). Found in the #143
parity review and filed as #148.
