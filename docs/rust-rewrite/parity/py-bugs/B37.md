# B37: An `auth_last_checked` with a UTC offset crashes startup

- Id: B37
- Status: open
- Python reference: `lib/config.py` `CacheSettings.auth_last_checked`, `ui/app.py` `LazyGithub.authenticate_with_github`
- Recommendation: Rust converts an offset timestamp to local time on load and saves it naive, as Python writes it.
- Rows: `config.cache-auth-last-checked`

`auth_last_checked` is a pydantic `datetime`, so a hand-edited value with an offset (`"2026-01-02T03:04:05+02:00"`)
loads as an aware datetime and is saved back with the offset. At startup, `authenticate_with_github` computes
`datetime.now() - auth_last_checked`, a naive minus an aware datetime, which raises `TypeError` and stops the app.
Python itself only ever writes naive local time (`datetime.now()`), so the value only comes from a hand edit or another
tool. The Rust loader already converts an offset timestamp to local civil time (`config/lax.rs`); the config parsing
golden (#159) records Python's load as an expected difference that names this bug.

Found while designing #152.
