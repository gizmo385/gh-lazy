# B39: A list or object as `appearance.theme` crashes startup

- Id: B39
- Status: answered
- Answer: Reject a list or object as a config error at `appearance.theme`, so the broken-config error shows instead of a crash. A config doctor command to repair such files is filed for M5. (Chris, 2026-10-25, in a Claude Code session)
- Python reference: `lib/config.py` `AppearanceSettings.validate_theme`
- Recommendation: Rust loads any value that isn't a built-in theme name, a list or object included, as `textual-dark`,
  which the next save writes back, as Python does for every other value.
- Rows: `config.appearance-theme`

`validate_theme` is a `mode="before"` validator that returns `BUILTIN_THEMES.get(theme_name, BUILTIN_THEMES["textual-dark"])`.
For an unknown string, a number or `null` this falls back to `textual-dark`. For an unhashable value, such as
`{"name": "nord"}` or `["nord"]`, `dict.get` raises `TypeError` ("cannot use 'dict' as a dict key"). pydantic only turns
`ValueError` and `AssertionError` into a `ValidationError`, so the `TypeError` escapes `Config.load_config` and the app
stops with a traceback before anything is drawn. The value only comes from a hand edit: the Settings modal offers the
built-in names.

The config parsing golden (#159) records Python's result for `{"name": "nord"}` as `"result": "exception"`, and the
Rust test lists the case in `PARSE_DIFFS`, naming this bug.

Found while implementing #159.
