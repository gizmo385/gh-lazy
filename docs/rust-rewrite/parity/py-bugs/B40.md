# B40: The search box pushes the bottom of a full table out of view

- Id: B40
- Status: open
- Python reference: `ui/widgets/common.py` `SearchableDataTable.compose`, `ToggleableSearchInput`; Textual 8.2.5
  `DataTable.DEFAULT_CSS` (`height: auto; max-height: 100%`)
- Recommendation: Lay the table out in the rows left below the box, so every row the cursor reaches is drawn and the
  horizontal scrollbar stays visible. Rust copies Python's layout until this is answered, so `table-search` matches.
- Rows: `searchable-tables.search`

`SearchableDataTable` is a `Vertical` holding the search box (3 rows and `margin-bottom: 1`) above the `DataTable`.
The table's `max-height: 100%` is a percentage of the container, not of the rows the box leaves, so a table with more
rows than fit stays as tall as the whole container and the container clips its bottom 4 rows. In the repos section at
160x48 (15 rows inside the box), opening the search box shows the header and 10 rows, while the table believes 13
body rows are visible: its horizontal scrollbar is clipped away, and `j` moves the cursor into the 3 hidden rows
without scrolling. After 12 presses of `j` no row on screen is highlighted; after 15 the table has scrolled by 3 and
the cursor is still out of view. A table whose rows all fit (a filtered one) isn't affected.

Found while implementing #169 with Python-only probes (`/`, typing `service`, `enter`, then `j` 12 and 15 times, on
`repos-60` at 160x48).
