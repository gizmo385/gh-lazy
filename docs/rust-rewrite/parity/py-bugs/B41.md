# B41: The main screen crashes when git isn't installed

- Id: B41
- Status: open
- Python reference: `lib/git_cli.py` `current_local_repo_full_name`; `ui/widgets/repositories.py` `load_repos`, `check_current_directory_repo`
- Recommendation: Treat "git can't be run" like "not a git repo": no current-directory repo, logged at debug, and the main screen loads as usual.
- Rows: `infrastructure.git-detection`, `repositories.auto-select-cwd-repo`

`current_local_repo_full_name` runs `git remote get-url origin` with `check_output` and catches only
`SubprocessError`. When `git` isn't on `PATH`, `check_output` raises `FileNotFoundError`, an `OSError`, which escapes.
It's raised inside the `load_repos` worker (`@work`, so `exit_on_error=True`) by the first
`check_current_directory_repo`, before the repos are fetched, so the app exits with a traceback as soon as the main
screen mounts. `gh` doesn't need `git`, so a machine with only `gh` installed can authenticate and then crashes.

The same pattern is in `current_local_branch_name` and `current_local_commit` (M3 and M4 callers), and in the
branch-exists, upstream and push helpers, which catch `SubprocessError` only too.

Found while designing #170 and #115, by reading the code. Not reproduced under the parity harness, whose `PATH`
always has `git`.
