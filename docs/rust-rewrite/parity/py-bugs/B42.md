# B42: The current-directory repo must match the table's case exactly

- Id: B42
- Status: open
- Python reference: `ui/widgets/repositories.py` `check_current_directory_repo`; `lib/git_cli.py` `current_local_repo_full_name`
- Recommendation: Match the remote's `owner/name` against the table's `full_name` ignoring ASCII case, as GitHub does.
- Rows: `repositories.auto-select-cwd-repo`

`check_current_directory_repo` looks the remote's `owner/name` up in the table's items with `dict.get`, keyed by the
API's `full_name`. GitHub owner and repo names are case-insensitive, and a clone keeps the case it was cloned with:
after `git clone https://github.com/Gizmo385/GH-Lazy`, `origin` is `Gizmo385/GH-Lazy` while the table holds
`gizmo385/gh-lazy`, so the repo is never auto-selected. Matching ignoring ASCII case selects the table's repo (with
the API's spelling, which is what the status bar and the details title then show).

Found while designing #170, by reading the code. The harness can't show it: its remotes are always the fixture's
lowercase names.
