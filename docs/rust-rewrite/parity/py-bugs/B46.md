# B46: Table cells parse GitHub text as markup

- Id: B46
- Status: open
- Python reference: Textual `widgets/_data_table.py` `default_cell_formatter` (`Text.from_markup` on every `str` cell); `ui/widgets/pull_requests.py` `pull_request_to_cell`; `ui/widgets/issues.py` `issue_to_cell`; `ui/widgets/workflows.py` `workflow_run_to_cell`
- Recommendation: Draw GitHub's text as typed. Sorting and the `/` search keep using the raw strings, as they already do.
- Rows: `searchable-tables.cell-markup`, `pull-requests.columns`, `issues.columns`, `workflows.columns`

Textual's `DataTable` turns each `str` cell into `Text.from_markup`, and the tables pass titles, logins and workflow
names straight through. Checked against Textual 8.2.5's formatter:

- `[docs] Fix` shows as ` Fix`, and `fix [x] box` as `fix  box`: a lowercase `[tag]` is taken as a style and vanishes;
- `[bold]x` shows a bold `x`, and `[link=...]` makes a link;
- `fix [/x] thing` raises `MarkupError` (closing tag with no open tag) while the row is drawn;
- `[WIP] thing` is kept, because a tag has to start with a lowercase letter, `#`, `/` or `@`.

Bracketed prefixes such as `[docs]`, `[ci]` or `[bug]` are common in PR and issue titles. The notifications table
(M4) shows titles the same way. The repos table's `[green]★[/]` is the app's own markup and isn't affected.

Found while speccing #171, #172 and #173. Until Chris answers, the recommendation stands and the specs follow it.
