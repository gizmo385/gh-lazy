# B47: The gh backend drops blank lines and header-shaped lines from raw response bodies

- Id: B47
- Status: answered
- Answer: Show the README verbatim. (Chris, 2026-10-26, in a Claude Code session; see #219)
- Python reference: `lib/github/backends/cli.py` `_parse_cli_api_response`; `lib/github/repositories.py`
  `get_repo_readme`; `ui/widgets/repository_details.py` `RepoOverviewTabPane.load_readme`
- Recommendation: Use the response body verbatim, as `GhResponse::text` already does, so a README renders the way
  GitHub shows it: paragraphs stay apart, fenced code keeps its blank lines, and no line goes missing. The
  `repo-overview` scenario's `py-bug-b47` capture checks only titles and focus until this is answered.
- Rows: `repositories.overview-tab`, `markdown-links.rendering`

With `api.client_type = "GITHUB_CLI"`, every response comes from `gh api -i`, and `_parse_cli_api_response` splits
its stdout into lines and sorts them by shape: it skips every empty line, takes every line matching
`^([a-zA-Z-]+)\:(.+)$` as a response header, and joins what's left with `\n` as the body. That works for JSON bodies,
which `gh` prints on one line, but a raw body such as a README (`Accept: application/vnd.github.raw`) loses all its
blank lines, and any line that starts with a word and a colon, such as `Note: ...` or `Usage: ...`, disappears into
the headers.

Markdown then parses a different document. Two paragraphs separated by a blank line become one paragraph, a blank
line inside a fenced code block is gone, and a `Note:` line never shows. In the `repo-overview` scenario,
`parity-bot/dotfiles`' README is

```
# dotfiles

The first paragraph.

A second paragraph, after a blank line.

Note: a line shaped like an HTTP header.

    (a fenced sh block: echo one, a blank line, echo two)
```

and Python shows "The first paragraph. A second paragraph, after a blank line." as one wrapped paragraph, no
"Note:" line, and `echo one` directly above `echo two`.

The same parser handles every raw body (diffs and job logs too), but diff lines start with a space, `+` or `-`, so
blank-line loss there is rarer; those rows are checked by their own specs.
