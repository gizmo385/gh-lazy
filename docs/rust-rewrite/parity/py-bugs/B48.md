# B48: The Repo Overview reads the repo description as Textual markup

- Id: B48
- Status: answered
- Answer: Show the description as literal text. (Chris, 2026-10-26, in a Claude Code session; see #219)
- Python reference: `ui/widgets/repository_details.py` `RepoOverviewTabPane.compose`
- Recommendation: Show the description as literal text. A description with `[` in it then reads as typed, and
  `[/]` no longer crashes the app.
- Rows: `repositories.overview-tab`

`compose` builds the description line with `Content.from_markup(f"\n{self.repo.description}")`, so anything in the
description that looks like Textual markup is applied instead of shown. `a [b]bold[/b] c` renders as "a bold c" with
"bold" in bold, `[link=x]y[/link]` becomes a link, and a stray closing tag such as `x [/] y` raises `MarkupError` from
`compose`, which takes the app down when the repo is selected. Text without a closing tag (`arr[0] = 1`, `foo [bar`)
shows as typed.

The repo name, owner login and default branch go through the same markup, but GitHub doesn't allow `[` in repo names
or logins, and git doesn't allow it in branch names, so only the description is affected. B11 is the same kind of
bug in the issue overview title.
