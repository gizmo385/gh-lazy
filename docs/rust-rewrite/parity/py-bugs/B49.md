# B49: The User profile modal reads profile fields as Textual markup

- Id: B49
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-26, in a Claude Code session; see #221 to #228)
- Python reference: `ui/screens/user_profile.py` `_format_field`, `UserProfileContainer.compose`
- Recommendation: Show every profile field as literal text, as B48's answer does for the repo description. Only
  the app's own bold labels, the bold name and the dim heading are styled.
- Rows: `modals.user-profile-header`

`UserProfileContainer.compose` builds each `Label` with `Content.from_markup` from text GitHub returns and the user
controls: the header (`f"[b]{header_name}[/b] ({profile_link}) — {kind}"`, where `header_name` is the display name),
and the Company, Location, Email, Blog and Twitter lines (`_format_field` returns
`f"[bold]{label}:[/bold] {value}"`). A name or company like `Acme [b]Labs[/b]` renders as "Acme Labs" with "Labs"
bold, `[red]` turns the rest of the line red, and an unmatched closing tag such as `[/x]` raises `MarkupError` while
the modal composes, which crashes the app. The profile link is built the same way: a login can't hold `[` or `]`,
but `html_url` is interpolated into `[link="..."]` unescaped.

The bio goes through `Markdown`, which is the intended rendering, and the repos table's Description cells are
`DataTable` cells, which are B46's (answered: drawn as typed).

Found while designing the User profile modal, by reading the code. The `user-profile` scenario's fixtures use plain
text, so the references don't depend on the answer.
