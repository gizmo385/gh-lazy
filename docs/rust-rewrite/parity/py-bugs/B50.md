# B50: The User profile modal's footer is drawn as an empty bordered strip

- Id: B50
- Status: open
- Python reference: `ui/screens/user_profile.py` `UserProfileModal.DEFAULT_CSS`, `UserProfileModal.compose`;
  Textual 8.2.5 `widgets/_footer.py` (`Footer` is a `ScrollableContainer`)
- Recommendation: Draw the usual modal footer on the bottom row, as every other modal has: ` q Close`, plus the
  focused field's shown bindings (none today). The `user-profile` scenario doesn't check the footer until this is
  answered.
- Rows: `modals.user-profile`

`UserProfileModal.DEFAULT_CSS` styles the dialog with the selector `UserProfileModal > ScrollableContainer`
(`width: 90; max-height: 90%; border: thick $background 80%; background: $surface-lighten-1`). Textual's `Footer`
is itself a `ScrollableContainer`, and the modal yields its `LazyGithubFooter` as a direct child too, so the rule
matches the footer as well. The footer becomes a 90-column box with a thick border, docked at the bottom-left, two
rows tall with its key row hidden inside the border: the modal shows no bindings at all, and the strip covers the
bottom-left of the dimmed main screen, whose own footer text shows to the right of it until the next refresh.

Seen in the `user-profile` scenario's Python references (`open`, `tabbed`): the last two rows are `█▀▀…▀█` and
`█▄▄…▄█`, 90 columns wide, and the footer the harness extracts from the bottom row is the strip's edge. The strip
also takes its two rows out of the height the dialog's `max-height: 90%` is measured against.

Found while designing the User profile modal.
