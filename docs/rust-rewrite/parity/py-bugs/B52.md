# B52: Lookup repository sends an untouched empty name to GitHub

- Id: B52
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-26, in a Claude Code session; see #221 to #228)
- Python reference: `ui/screens/lookup_repository.py` `LookupRepositoryModal.action_submit`; Textual 8.2.5
  `widgets/_input.py` `Input.is_valid` (`_valid` starts `True`)
- Recommendation: Validate the text when the lookup is submitted, so an empty or malformed name always toasts
  error / "Validation Error" "You must enter a repo name!" and sends nothing.
- Rows: `modals.lookup-repository`

`action_submit` checks `repo_input.is_valid`, which is the result of the input's last validation. Textual validates
an `Input` on blur, on change and on submit, and `_valid` starts out `True`. So straight after the modal opens, with
the input focused and empty, `modal.submit` (`shift+enter`) passes the check and looks up `""`: the app sends
`GET /repos/` and, when that fails, toasts "Could not find repo!" instead of "You must enter a repo name!". Any blur
or keystroke validates the input first, which is why tabbing to Lookup and pressing enter on an empty input shows
the right toast (the `repo-lookup` scenario's `empty` capture).

The parity harness can't send `shift+enter`, so there's no capture of the bad path; it's from reading the code.

Found while designing the Lookup repository modal.
