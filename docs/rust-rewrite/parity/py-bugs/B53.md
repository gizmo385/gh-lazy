# B53: Cached rows the live fetch no longer returns stay in the table and the cache

- Id: B53
- Status: open
- Python reference: `ui/widgets/common.py` `SearchableDataTable.initialize_from_cache`, `add_items`,
  `save_to_cache`; `ui/widgets/pull_requests.py` and `ui/widgets/issues.py` `on_issues_and_pull_requests_fetched`;
  `ui/widgets/workflows.py` `WorkflowRunsContainer.load_repo`
- Recommendation: When a repo's first page arrives, it replaces the rows restored from the cache, and the cache is
  rewritten from the table as usual. A failed first page keeps the cached rows, as in Python. The cached rows still
  sit under the loading overlay until then, so the cache's visible job is unchanged: rows when GitHub can't be
  reached.
- Rows: `searchable-tables.row-cache`, `caches-drafts.pull-requests-json`, `caches-drafts.issues-json`,
  `caches-drafts.workflow-runs-json`

Selecting a repo restores the PR, issue and workflow-run tables from `<owner>_<repo>_<name>.json`, then fetches the
first page and adds it with `add_items`, which replaces rows with the same number and keeps the rest. The table is
then saved back to the cache, every row included. Nothing ever removes a cached row that the first page doesn't
return, so:

- rows from pages loaded lazily on an earlier visit come back on top of the first page, and the table starts with
  more rows than a fresh fetch gives;
- an issue that was deleted or transferred, or a PR or issue that fell out of the configured filters (an
  `owner_filter` changed to "mine", a `state_filter` changed to "open"), stays in the table with its old status
  for good, and is written back to the cache on every visit;
- a run deleted on GitHub stays in the Workflows table.

The loading overlay covers each table while the cache is restored and until the first page lands, so on success
the user never sees the cache by itself, only these leftovers. The `table-caches` scenario covers the path both
apps agree on: the first page fails and the cached rows are what's left.

The repos table doesn't have this problem: `load_repos` clears it before adding the fetched repos.

Found while designing the local table caches.
