# B54: Review comments' reactions are asked for on the issue-comment endpoint

- Id: B54
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-26, in a Claude Code session; see #230)
- Python reference: `ui/widgets/pull_requests.py` `PrConversationTabPane.fetch_reactions`; `lib/github/reactions.py`
  `list_reactions_on_comment`
- Recommendation: Ask for a review comment's reactions on `GET /repos/{owner}/{repo}/pulls/comments/{id}/reactions`
  and an issue comment's on `GET /repos/{owner}/{repo}/issues/comments/{id}/reactions`, so the reactions on inline
  review comments show under them like the ones on issue comments.
- Rows: `pull-requests.comment-reactions`

Once the PR Conversation tab has its reviews and comments, `fetch_reactions` asks for the reactions of every issue
comment and of every review comment in every review, all through `list_reactions_on_comment`, which always uses
`/repos/{owner}/{repo}/issues/comments/{id}/reactions`. Review comments (`pull_request_review_id` set) live in a
different id space, on `/pulls/comments/{id}`: GitHub answers 404 for their ids on the issue-comment endpoint, the
error is logged at debug ("Could not find comment with ID ..."), and no reactions ever show under a review comment.
If an issue comment happened to share the id, its reactions would show under the review comment instead.

In the `pr-details` scenario's fixtures, review comment 9001 has a 👀 reaction on `/pulls/comments/9001/reactions`;
Python asks for `/issues/comments/9001/reactions` (a 404) and shows none.

Found while designing the PR Conversation tab.
