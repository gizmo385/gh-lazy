# B55: The diff parser strips leading `a`, `b`, `/`, `-`, `+` and spaces from file paths

- Id: B55
- Status: open
- Python reference: `lib/diff_parser.py` `_parse_file_from_diff` (`current_line.lstrip("--- a/")`,
  `current_line.lstrip("+++ b/")`); `ui/widgets/split_diff_viewer.py` `_format_file_header`, `filter_files`
- Recommendation: Take the path after the exact `--- a/` and `+++ b/` prefixes (`/dev/null` for an added or deleted
  side), so `build.rs` shows as `build.rs`, the file filter matches the real path, and M3's review comments (#187) go
  to the right `path`.
- Rows: `diff-viewer.file-header`, `diff-viewer.file-filter`, `diff-viewer.diff-parser`

`str.lstrip` takes a set of characters, not a prefix. `"+++ b/build.rs".lstrip("+++ b/")` strips every leading `+`,
space, `b` and `/`, giving `uild.rs`; `"--- a/app/main.py".lstrip("--- a/")` gives `pp/main.py`. The `+++` side names
the file, so any path starting with `b` or `/` loses those characters; a deleted file is named by its `---` side, so
there a leading `a` is lost (`--- a/assets/old.css` becomes `ssets/old.css`). `/dev/null` only works because the
mangled `dev/null` is what `FILE_DELETED_SENTINEL` expects.

The mangled path is what the Diff tab shows (`📄 uild.rs (+1)` in the `pr-diff` scenario), what the file filter
matches (typing `build` hides `build.rs`), the lexer guess for syntax colors, and the `path` the submitted review's
comments carry, which GitHub then rejects or puts on the wrong file.

Found while designing the PR Diff tab.
