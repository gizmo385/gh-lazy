# B56: With the gh backend, every diff error reads "Error fetching diff (0)"

- Id: B56
- Status: open
- Python reference: `ui/widgets/pull_requests.py` `PrDiffTabPane.fetch_diff`; `lib/github/pull_requests.py`
  `get_diff`; `lib/github/backends/cli.py` `run_gh_cli_command`, `_parse_cli_api_response`
- Recommendation: Fetch the diff with `gh api` and `Accept: application/vnd.github.diff` (with `-i`, as every other
  request), and show what the code intends: "No diff contents found" for a 404, "Diff too large" for a 406 and
  "Error fetching diff (<status>)" otherwise.
- Rows: `pull-requests.diff-tab`

With `api.client_type = "GITHUB_CLI"`, `get_diff` runs `gh pr diff -R <owner>/<repo> <number>` instead of an API
call. Its output has no `HTTP/2.0 <status>` line, so `_parse_cli_api_response` leaves `http_status` at 0, and a
failure raises `GithubApiRequestFailed` with status 0. The tab's 404 ("No diff contents found") and 406 ("Diff too
large") branches never run: a missing PR and a diff over GitHub's 20,000-line limit both show
`Error fetching diff (0)`, as in the `pr-details` scenario's `diff-error` capture (PR 4's diff answers 406).

Found while designing the PR Diff tab.
