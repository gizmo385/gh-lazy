# B57: PR Overview section titles can stay cut to their placeholder's width

- Id: B57
- Status: open
- Python reference: `ui/widgets/pull_requests.py` `PrOverviewTabPane.compose`, `load_checks`, `add_reviews`; Textual
  8.2.5 `widgets/_collapsible.py` `CollapsibleTitle`
- Recommendation: Draw the whole title once it's known ("Status checks: ✓ Passed", "PR Reviews: ✘ Changes
  Requested"), cut only by the pane's width. Textual-only layout race, not reproduced.
- Rows: `pull-requests.overview-checks`, `pull-requests.overview-reviews`, `pull-requests.collapsible`

The Overview's checks and reviews sections start with placeholder titles, "Status Checks: ..." and "Reviews: ...".
When the checks and the conversation load, `load_checks` and `add_reviews` set the real titles. A Collapsible's title
widget is sized to its content, and in some runs it isn't laid out again after the change, so the new title is drawn
in the old width: "Status checks: ✓" instead of "Status checks: ✓ Passed", or "PR Reviews:" instead of "PR Reviews:
✘ Changes Requested". Which title is cut, if any, depends on the order the requests answer, so it changes from run
to run. Seen in Python-only runs of the `pr-details` scenario, which therefore only checks the start of each title.

The status, the part that's lost, is the point of the title.

Found while designing the PR Overview tab.
