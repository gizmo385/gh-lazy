# B58: A failed status-checks request crashes the app

- Id: B58
- Status: open
- Python reference: `ui/widgets/pull_requests.py` `PrOverviewTabPane.load_checks`; `lib/github/checks.py`
  `combined_check_status_for_ref`, `check_runs_for_ref`
- Recommendation: Don't crash. When either checks request fails, log an ERROR line ("Error loading status checks")
  and show the checks section with the title "Status checks: failed to load" and nothing inside, as B16 recommends
  for the other sections that load after the PR (the wording is part of the B16 answer).
- Rows: `pull-requests.overview-checks`

`load_checks` runs both checks requests with `asyncio.gather` in a `@work` worker and catches nothing. When either
answers with an HTTP error, `raise_for_status` raises `GithubApiRequestFailed`, the worker fails, and Textual's
default `exit_on_error` ends the app with a traceback. A Python-only probe (PR 4 of the `pr-details` fixtures with its
`commits/<sha>/status` answered by a 500; not committed) exited during the selection with the traceback ending in
`checks.py:12 in combined_check_status_for_ref`. Selecting a PR whose checks GitHub can't serve at that moment ends
the session.

B16 lists the PR checks among the spinners that never clear; with the gh backend the checks worker ends the app
instead.

Found while designing the PR Overview tab.
