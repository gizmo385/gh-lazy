# B59: `enter` in the diff filter focuses a hunk pane that isn't shown

- Id: B59
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-26, in a Claude Code session; see #230)
- Python reference: `ui/widgets/split_diff_viewer.py` `SplitDiffViewer.on_filter_submitted`
- Recommendation: Move focus to the first shown file's first hunk: its pane when the hunk is open, else the hunk's
  title, so something visible has focus and `j` / `k` or `enter` work at once.
- Rows: `diff-viewer.file-filter`

`on_filter_submitted` blurs the filter and focuses the first `UnifiedDiffPane` whose own `display` is true. Every
pane's own `display` is true; what hides a pane is its hunk's closed `Collapsible`, and hunks start closed. So
`enter` usually sends focus to a pane inside a closed hunk, which can't be seen: in the `pr-diff` scenario's
Python-only probe (`/`, `view`, `enter`; not committed) the filter lost its focus border and nothing on screen
showed focus afterwards, so the next `tab` or `j` had no visible starting point.

Found while designing the PR Diff tab.
