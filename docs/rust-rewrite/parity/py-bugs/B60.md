# B60: A failed issue-comments request crashes the app

- Id: B60
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-26, in a Claude Code session; see #239 and #240)
- Python reference: `ui/widgets/issues.py` `IssueConversationTabPane.fetch_issue_comments`; `lib/github/issues.py` `get_comments`
- Recommendation: Don't crash. Log ERROR `Error retrieving issue comments` (the error itself at debug), clear the loading overlay, and show `No comments available`, as the Workflows section treats a failed fetch as an empty list (#173). No toast.
- Rows: `issues.comments-tab`, `issues.comments-error`

Selecting an issue mounts its Comments tab, whose `@work` worker `fetch_issue_comments` calls `get_comments`. That
calls `raise_for_status`, and nothing catches the `GithubApiRequestFailed`, so any HTTP error (a 500, a 403 from a
rate limit, a `gh` failure) takes the worker down, and Textual's default `exit_on_error` exits the app with a
traceback. A body that doesn't decode (a comment with an unknown `author_association`) does the same through
pydantic. The `issue-details` fixture's issue 9 answers its comments with a 500; selecting it in Python exits the app
about a second later, whichever tab is showing.

This is a crash rather than Py bug B16's never-clearing spinner, which the matrix listed for this tab. The PR
Conversation tab catches the same error (`Error retrieving PR reviews or comments`) and keeps its spinner, which is
B16.

Found while designing the issue details tabs. Until Chris answers, the recommendation stands and the specs follow it.
