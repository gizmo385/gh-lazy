# B61: Looking up a pull request's number as an issue adds the pull request to the Issues table

- Id: B61
- Status: open
- Python reference: `ui/screens/lookup_issue.py` `LookupIssueModal.action_submit`; `lib/github/issues.py` `get_issue_by_number`; `ui/widgets/issues.py` `IssuesContainer.action_lookup_issue`
- Recommendation: Select it as Python does (the details show its Overview and Comments, titled `Issue #N Details`), but don't add it to the Issues table, which lists only issues.
- Rows: `issues.lookup`, `issues.lookup-pull-request`

GitHub's `GET /repos/<owner>/<repo>/issues/<number>` answers for pull requests too, with `pull_request` and `draft`
keys. `get_issue_by_number` builds an `Issue` from whatever comes back, so `O` then a pull request's number succeeds:
the pull request's row (`#`, `open`, author, title) is added to the Issues table, which otherwise only ever holds items
without a `draft` key, and stays there until the next repo selection. The `issue-lookup` scenario's `py-bug-b61`
capture shows pull request 8 in the Issues table under issue 9.

Found while designing issue lookup. Until Chris answers, the recommendation stands and the specs follow it.
