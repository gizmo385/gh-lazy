# B65: A hunk with nothing on the new side is titled `Lines 0--1`

- Id: B65
- Status: open
- Python reference: `ui/widgets/split_diff_viewer.py` `_format_hunk_header`
- Recommendation: When a hunk's new side is empty (`+N,0`), title it from the old side instead: `Line <a>` for one
  removed line, else `Lines <a>-<a+b-1>`, so a deleted file's `@@ -1,3 +0,0 @@` reads `Lines 1-3 (-3)`.
- Rows: `diff-viewer.diff-parser`, `diff-viewer.hunk-header`

`_format_hunk_header` always titles a hunk from its new-side range: `Line <c>` when `d == 1`, else
`Lines <c>-<c+d-1>`. A hunk whose new side is empty has `d == 0`, so the end comes out one before the start. A deleted
file's only hunk (`@@ -1,3 +0,0 @@`) reads `Lines 0--1 (-3)`, and a hunk that only removes lines mid-file
(`@@ -12,2 +11,0 @@`) reads `Lines 11-10 (-2)`. Neither names the lines the hunk shows, which are all on the old side.

Found while implementing the diff parser (#235); raised by Chris on 2026-10-26.
