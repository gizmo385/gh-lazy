# B68: A refused workflow dispatch reports success

- Id: B68
- Status: open
- Python reference: `lib/github/workflows.py` `create_dispatch_event`; `lib/github/backends/cli.py` `CliApiResponse.is_success`
- Recommendation: Report the failure: toast error / "Error Triggering Build" "Could not trigger build - are you sure this workflow supports dispatch events?" and keep the modal open.
- Rows: `modals.trigger-workflow`, `toasts.workflow-triggered`

`create_dispatch_event` catches the request's failure and then returns `response.is_success`. With the gh backend
(the only one the Rust app has), `is_success` is a method, not a property, so the function returns the bound method,
which is always true. A dispatch GitHub refuses (a workflow without a `workflow_dispatch` trigger answers 422) closes
the modal and toasts "Successfully triggered workflow"; the "Error Triggering Build" toast is never shown. The
re-run functions return the same expression, but only after `raise_for_status` succeeded, so they're unaffected.
