# B70: A failed issue create or update crashes the app

- Id: B70
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-27, in a Claude Code session; see #175)
- Python reference: `ui/screens/new_issue.py` `NewIssueContainer.create_issue`; `ui/screens/edit_issue.py` `EditIssueContainer.submit_updated_issue`; `lib/github/issues.py` `create_issue`, `update_issue`
- Recommendation: Keep the modal open with the text as typed and toast an error: error / "Error creating issue" "Could not create the issue" for New issue, error / "Error updating issue" "Could not update issue #N" for Edit issue (and, per B69's recommendation, Save enabled again).
- Rows: `modals.new-issue`, `modals.edit-issue`

`create_issue` and `update_issue` call `raise_for_status()`, and neither modal catches what it raises
(`GithubApiRequestFailed` with the gh backend). Any failure (no permission, a deleted repo, a validation error from
GitHub, gh not logged in any more) ends the app with a traceback, and the typed title and body are lost. The New
comment modal has the same gap (Py bug B17).

Edit issue has a second way into the same crash: its Status select offers a blank first row (`allow_blank` is on), and
picking it sends `"state": "Select.NULL"`, which GitHub refuses. Recommendation: leave `state` out of the request when
the blank row is picked, so the state doesn't change.
