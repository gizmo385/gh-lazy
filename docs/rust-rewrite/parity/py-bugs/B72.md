# B72: The current-directory branch overwrites a restored draft's Compare branch

- Id: B72
- Status: open
- Python reference: `ui/screens/create_or_edit_pull_request.py` `BranchSelection.on_mount`, `BranchSelection.set_default_branch_value`, `CreateOrEditPullRequestContainer.on_mount`, `_restore_draft_state`
- Recommendation: Restore the draft after the current-directory prefill, so the saved Compare branch wins; with no draft, the prefill stays as it is.
- Rows: `modals.pr-drafts`

When the selected repo is the repo LazyGithub was started in, `BranchSelection.on_mount` starts the worker
`set_default_branch_value`, which sets Compare to the current-directory branch. The worker runs after the
container's `on_mount` has restored the saved draft, so the draft's `head_ref` is replaced by the local branch,
and the debounced save that the restore scheduled writes that branch back into the draft 2 s later. A user who saved
a draft for another branch and reopens Create PR from a checkout of a different branch silently gets the checkout's
branch, while every other field comes from the draft. Found by reading the code (#186); the seeded
`pr-drafts-restore` scenario (#186, after #229) shows it once a variant with a matching `git_remote` and another
`git_branch` runs.
