# B73: A PR added to the table after Create PR shows a cut number

- Id: B73
- Status: open
- Python reference: `ui/widgets/common.py` `SearchableDataTable.add_item`; `ui/screens/primary.py` `SelectionsPane.trigger_pr_creation_flow`
- Recommendation: Widen the column to the new number and draw every row with the new widths: the created PR shows as `10`.
- Rows: `modals.create-pr-submit`

After Create PR succeeds, `add_item` adds the new PR to the Pull Requests table and sorts it. When the new number is
wider than every number already in the table (PR 10 in a table of PRs 2 to 5), the `#` column keeps its old width
in the header and in the rows Textual had already drawn, and the new row is drawn as `1` instead of `10`; one older
row is redrawn at the new width, so the columns no longer line up (`2   open` under `#  Status`). Seen in the
`pr-new` scenario (`created` capture). Issue create (#258) has the same path but its fixture numbers are already
two digits wide.
