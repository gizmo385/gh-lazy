# B74: Git output from the Create PR checks is written over the screen

- Id: B74
- Status: answered
- Answer: Follow the recommendation. ([Chris, 2026-10-30](https://github.com/gizmo385/gh-lazy/issues/317#issuecomment-6515229902))
- Python reference: `lib/git_cli.py` `does_branch_exist_on_remote`, `does_branch_have_configured_upstream`; `ui/screens/create_or_edit_pull_request.py` `ensure_branch_exists_on_remote`, `ensure_directory_branch_has_configured_upstream`
- Recommendation: Capture both of git's output streams for every check and log them at debug; nothing reaches the terminal.
- Rows: `modals.create-pr-upstream-warning`, `modals.create-pr-push-prompt`

`does_branch_exist_on_remote` runs `git ls-remote origin <branch>` with `check_output`, which captures stdout but
lets stderr through, and `does_branch_have_configured_upstream` runs `git config --get branch.<b>.merge` with
`run`, which lets both through. The child writes straight to the terminal under Textual: outside a git repo the
`pr-new` scenario's raw output holds `fatal: 'origin' does not appear to be a git repository` and `fatal: Could
not read from remote repository.`, and a branch with an upstream prints its merge ref (`refs/heads/<b>`) when
Create PR opens. The text stays on screen until Textual redraws those cells.
