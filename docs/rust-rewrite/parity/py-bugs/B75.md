# B75: Edit PR on a pull request that fails to load crashes the app

- Id: B75
- Status: answered
- Answer: Follow the recommendation. ([Chris, 2026-10-30](https://github.com/gizmo385/gh-lazy/issues/317#issuecomment-6515229902))
- Python reference: `ui/widgets/pull_requests.py` `PullRequestsContainer.action_edit_pull_request`; `lib/github/pull_requests.py` `get_full_pull_request`
- Recommendation: Toast error / "API Error" "Error fetching pull request!" (the toast selecting that row already gives) and open no dialog.
- Rows: `pull-requests.edit-from-table`

`E` on the Pull Requests table fetches the full pull request first. `get_full_pull_request` calls
`raise_for_status`, and nothing in the worker catches the exception, so a pull request whose fetch fails (a 500, a
network error, a deleted PR) takes the whole app down with a traceback. Selecting the same row with Enter toasts
error / "API Error" "Error fetching pull request!" instead.
