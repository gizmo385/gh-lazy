# B77: A refused review request still reports success

- Id: B77
- Status: open
- Python reference: `lib/github/pull_requests.py` `request_reviews`; `ui/screens/create_or_edit_pull_request.py` `_edit_pr`, `_create_pr`
- Recommendation: Keep the success toast and closing the dialog (the pull request was updated or created), and add a toast error / "Error requesting reviews" "Could not request reviews from <logins>" when the review request fails.
- Rows: `modals.edit-pr`

`request_reviews` catches a failed `POST .../pulls/<n>/requested_reviewers` (GitHub answers 422 for a login that
isn't a collaborator, an organization, or the PR's author), logs "Error creating review requests" and returns
`False`, which both callers ignore. Edit PR then toasts "Successfully updated PR!" and Create PR "Successfully created
PR!", so the user believes reviews were requested when none were (Create PR's row, `modals.create-pr-submit`, is
left to #184's design to tag). The Reviewers input accepts any existing user, collaborator or not, so this is easy to hit.
