# B78: Replacing the details while a section is maximized leaves a blank screen

- Id: B78
- Status: open
- Python reference: `ui/app.py` `action_maximize`; Textual 8.2.5 `Screen.maximize`, `Screen.maximized`; `ui/screens/primary.py` `MainViewPane.load_pull_request`
- Recommendation: When the maximized section leaves the screen (its details are replaced or reloaded), restore the layout as `escape` would, with focus where it is.
- Rows: `pull-requests.collapsible`, `main-layout.maximize`

A focus key moves focus while a section stays maximized (`main-layout.maximize`). So `M` on a PR Overview section,
then `2`, `j`, `enter`, selects another PR behind the maximized view. The details are rebuilt, the maximized
`Collapsible` is removed from the DOM, and Textual keeps `Screen.maximized` pointing at it. The screen then shows only
the `╱` hatch, with no footer, until the user presses `escape`, which brings back the main layout with the new PR's
details. Found while designing #248 (probe: `pr-maximize` up to `focus-key`, then `j`, `enter`).

Nothing on the blank screen says what happened or how to get back. The one-time "View Maximized" toast has usually
expired by then. The same happens to any maximized widget inside the details that a reload replaces.
