# B81: A failed mark-read still moves the notification to Read

- Id: B81
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-28, on #190)
- Python reference: `lib/github/notifications.py` `mark_notification_as_read`; `ui/screens/notifications.py` `NotificationsContainer.notification_marked_read`, `NotificationsModal.handle_notification_selected`
- Recommendation: On `R`, when the `PATCH` fails, leave the notification in Unread, log `Failed to mark notification as read` at error and show it as an error toast. On Enter, open the notification anyway (opening is what the user asked for) and only log the error.
- Rows: `modals.notifications-errors`, `keybindings.notifications-mark-read`

`mark_notification_as_read` runs `gh --method PATCH api /notifications/threads/<id>` and never looks at the exit code
or HTTP status (`run_gh_cli_command` doesn't raise), so a refused or failed request is silent: not even the command log
shows it. The container then moves the row from Unread to Read as if it had worked, and the next fetch brings it back
as unread. Seen with a 500 fixture while speccing #189.
