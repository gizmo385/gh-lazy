# B83: PR notifications on GitHub Enterprise open only the repo

- Id: B83
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-28, on #190)
- Python reference: `lib/github/notifications.py` `_PULL_REQUEST_URL_REGEX`, `extract_notification_subject`
- Recommendation: Recognise `/repos/{owner}/{repo}/pulls/{n}` after any path prefix (GHE's `/api/v3`), so a GHE pull request notification opens the PR as a github.com one does. github.com URLs behave exactly as in Python.
- Rows: `modals.notifications-select`

The regex, `[^:]+:[\/]+[^\/]+\/repos\/([^\/]+)\/([^\/]+)\/pulls\/(\d+)`, wants `/repos/` right after the host. GitHub
Enterprise API URLs are `https://<host>/api/v3/repos/...`, so they never match, and a pull request notification there
opens only its repository with "Opening repository for notification". Found while speccing #190.
