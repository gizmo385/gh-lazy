# B84: A search brings a notification marked read back into Unread

- Id: B84
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-28, on #293)
- Python reference: `ui/screens/notifications.py` `_NotificationsTableTabPane.remove_notification`; `ui/widgets/common.py` `SearchableDataTable.handle_submitted_search`
- Recommendation: `R` removes the notification from the Unread table's items, not just its row, so no later search, page or `ctrl+r` sees it there.
- Rows: `modals.notifications-keys`, `modals.notifications-search`

`remove_notification` removes the row from the `DataTable` but leaves the notification in the table's `items`. A
search rebuilds the rows from `items`, so after `R`, submitting any search on Unread (even an empty one) shows the
notification there again, while it's also in Read. The stale item also counts towards the lazy-loading threshold.
Seen while speccing #189 (`R`, then `/` and enter).
