# B86: Command palette hits with equal scores come in a different order from run to run

- Id: B86
- Status: open
- Python reference: `ui/screens/primary.py` `LazyGithubMainScreen.COMMANDS`, `MainScreenCommandProvider.search`;
  Textual 8.2.5 `command.py` `CommandPalette._provider_classes`, `_search_for`, `_refresh_command_list`
- Recommendation: Use one fixed order: highest score first, and on equal scores LazyGithub's commands in their own
  order ("Toggle Command Log", "Toggle Workflows", "Toggle Issues", "Toggle Pull Requests", "Change Settings",
  "Debug Info", "Open Bug Report", "Refresh notifications"), then Textual's system commands in its order ("Theme",
  "Quit", "Keys", "Maximize" or "Minimize", "Screenshot").
- Rows: `command-palette.palette`

The palette asks two providers for hits, LazyGithub's `MainScreenCommandProvider` and Textual's
`SystemCommandsProvider`. Textual keeps them in a `set` of classes, so the order it starts their searches in depends
on the classes' hashes, which are their memory addresses and change from one run to the next. Each provider puts all
its hits on the queue before the other runs, and the final sort by score is stable, so hits with equal scores keep
whichever provider order that run had.

Typing `t` shows it: "Theme" and the four "Toggle …" commands all score 6.0, and "Quit", "Screenshot", "Change
Settings" and "Open Bug Report" all score 3.0. One Python run listed the toggles before "Theme" and "Change
Settings" before "Quit"; another, with the same inputs, listed "Theme" first and "Quit" before "Change Settings".
The order within one provider is always its own.

A user who types the same query twice in two sessions can find the highlighted (Enter) command differs. The Rust app
can't reproduce a random order, and either fixed order is one Python sometimes shows; the recommendation picks the
app's own commands first. Scenarios don't capture tied queries, so recordings don't depend on it.

Found while designing the command palette (#191, #300).
