# B87: LazyGithub's own commands aren't in the palette's opening list

- Id: B87
- Status: answered
- Answer: List LazyGithub's commands in the opening list too, after the system ones (the alternative, not the recommendation). (Chris, 2026-10-28, on #191)
- Python reference: `ui/screens/primary.py` `MainScreenCommandProvider` (no `discover`); Textual 8.2.5
  `command.py` `Provider.discover`, `system_commands.py` `SystemCommandsProvider.discover`
- Recommendation: Keep Python's behavior (only Textual's system commands in the opening list) for parity. The
  alternative is to list LazyGithub's commands there too, after the system ones.
- Rows: `command-palette.palette`

With an empty query, Textual's palette shows each provider's `discover` hits. Textual's system provider has one
(Keys, Maximize or Minimize, Quit, Screenshot, Theme, sorted by name); LazyGithub's `MainScreenCommandProvider`
implements only `search`, so its commands ("Toggle Command Log", "Toggle Workflows", "Toggle Issues", "Toggle Pull
Requests", "Change Settings", "Debug Info", "Open Bug Report", "Refresh notifications") appear only once the user
types something that matches them. Someone who opens the palette to see what it can do never sees the app's own
commands.

This looks like an omission rather than a choice, but changing it changes what users see, so it's for Chris to decide.

Found while designing the command palette (#191, #300).
