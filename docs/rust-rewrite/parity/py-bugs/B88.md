# B88: Hiding the focused section from the palette leaves nothing focused

- Id: B88
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-28, on #191)
- Python reference: `ui/screens/primary.py` `action_toggle_ui`; Textual 8.2.5 `screen.py` `Screen._move_focus`,
  `_update_auto_focus`, `maximize`
- Recommendation: When a toggle hides the section (or command log) that has focus, move focus to the first stop of
  the focus ring, which is the Repositories table (or its search box while that's shown); when it hides the
  maximized section, restore the layout first. This is an `intentional diff` once accepted.
- Rows: `main-layout.focus-lost`, `command-palette.toggle-command-log`, `command-palette.toggle-workflows`,
  `command-palette.toggle-issues`, `command-palette.toggle-pull-requests`

The palette's toggles set the widget's `display` to false. When the widget, or something inside it, had focus,
Textual drops focus and gives it to nothing:

- no pane border shows the focus color, and the footer shrinks to the screen's and the app's bindings
  (`^n Notifications  ^v Paste link  f Follow link  …  ? Keybindings`);
- table keys and `M` do nothing, and the palette offers no "Maximize";
- `tab` and `shift+tab` both focus the Repositories table (Textual focuses the first in the chain when nothing has
  focus), and so does closing any modal, the palette included (Textual's auto focus on a screen's resume);
- a focus key works as usual.

Hiding the section that's maximized is odder: the hidden section stays drawn maximized on the hatch until `escape`,
and then the layout comes back without it, with nothing focused.

Nothing is lost, but the screen looks as if the app stopped responding to the keyboard until the user presses a
focus key or `tab`. Reproducing it also needs a "nothing focused" state the Rust main screen doesn't have. The
recommendation lands focus where Python puts it on the next `tab` anyway.

Found while designing the command palette (#191, #301). Scenario `command-palette-commands`, capture `log-hidden`,
shows Python's side.
