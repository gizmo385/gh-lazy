# B89: Saving Settings with a select on its blank option crashes

- Id: B89
- Status: answered
- Answer: Follow the recommendation. ([Chris, 2026-10-28](https://github.com/gizmo385/gh-lazy/issues/193#issuecomment-6485805292))
- Python reference: `ui/screens/settings.py` `FieldSetting._field_to_widget`, `_update_settings`; `lib/config.py`
  `Config.save`; Textual 8.2.5 `widgets/_select.py` (`allow_blank=True`)
- Recommendation: Keep the blank "Select" option in the list, as Textual draws it, and have Save leave a field whose
  select is on the blank at the value it had when the modal opened. Nothing is written for that field, and the rest
  of the save goes ahead.
- Rows: `modals.settings-widgets`, `modals.settings-save`

Every select in the Settings modal (the theme, the two filters on Pull Requests and on Issues, the merge method and
the API client type) is a Textual `Select` with `allow_blank=True`, so its list starts with a blank option shown as
"Select". Picking it sets the select's value to `Select.BLANK`. Save copies that object into the config, and
`model_dump_json` then raises `PydanticSerializationError`: the app crashes with a traceback, `config.json` isn't
written, and the in-memory config is left half-updated. Reproduced on v0.6.6 with a pilot (theme select, `up` to the
blank, Save).

The recommendation keeps the overlay identical to Python's (the Rust `Select` always has the blank) and turns the
crash into a no-op for that one field.
