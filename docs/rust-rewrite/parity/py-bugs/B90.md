# B90: Settings saves text that isn't a valid value, and the next start fails

- Id: B90
- Status: answered
- Answer: Follow the recommendation. ([Chris, 2026-10-28](https://github.com/gizmo385/gh-lazy/issues/193#issuecomment-6485805292))
- Python reference: `ui/screens/settings.py` `FieldSetting._field_to_widget` (the text-input fallback),
  `_update_settings`; `lib/config.py` `CacheSettings`, `CoreConfig`
- Recommendation: Save checks every text field before writing anything. If one doesn't hold a valid value, nothing is
  saved, the modal stays open, and an error toast titled "Invalid setting" names the field and what it needs:
  "<Field Name> must be a whole number" (the cache durations and TTLs, `logfile_max_bytes`, `logfile_count`),
  "<Field Name> must be a date and time like 2026-10-24 18:30:05, or None" (`auth_last_checked`), or
  "<Field Name> can't be empty" (`cache_directory`, `logfile_path`).
- Rows: `modals.settings-values`

Every config field that isn't a bool, an enum, a theme, a list or an optional path gets a plain text input, and Save
stores the input's text as is (`setattr` on a pydantic model doesn't validate). With Py bug B2's fix, Rust saves
numbers as numbers, which leaves the text that doesn't parse: "abc" or "10m" in Default Ttl is written as the string
`"abc"`, and the next start fails to load the config (pydantic's `int` validation) until the file is edited or cleared.
The same goes for a malformed Auth Last Checked. A blank Cache Directory or Logfile Path is written as `"."`
(`Path("")`), so the caches or the log land in whatever directory the app was started from.

Python has no validation message to copy, so the toast text above is new. The alternative, keeping the field's old
value without saying so, loses the user's edit silently.
