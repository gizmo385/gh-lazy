# B93: Rebinding a key to its own default saves a redundant override

- Id: B93
- Status: answered
- Answer: Keep parity. ([Chris, 2026-10-28](https://github.com/gizmo385/gh-lazy/issues/194#issuecomment-6485805658))
- Python reference: `ui/screens/settings.py` `KeySelectionInput.on_key`, `_update_settings`
- Recommendation: Keep parity. Compare the recorded key name with the default key string as written, as Python does,
  so pressing `?` on "Keybindings" saves `"app.open_help": "question_mark"`. Python and Rust both read it back as `?`.
- Rows: `modals.settings-key-rebinding`

Save removes an override only when the row's value is the binding's default key string exactly. A row records
Textual's key name, so pressing a binding's own default key doesn't match when the default is written differently:
`?` is recorded as `question_mark` against the default `?`, `/` as `slash` against `/`, `^` as `circumflex_accent`.
The override that gets saved is harmless (it binds the same key) but clutters `config.json`, and the row shows
`question_mark` where it showed `?`. A default with two keys (`modal.close`'s `q, escape`) can't be restored by
pressing either key, only with `escape`, which resets the row.
