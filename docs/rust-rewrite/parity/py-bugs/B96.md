# B96: Copy to Clipboard copies the rendered debug text, not the markdown, and leaves it selected

- Id: B96
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-28, [comment](https://github.com/gizmo385/gh-lazy/issues/312#issuecomment-6485044235))
- Python reference: `ui/screens/debug.py` `DebugModal.action_copy`; Textual 8.2.5 `Markdown.text_select_all`,
  `Screen.action_copy_text`
- Recommendation: Copy the debug markdown itself, the same text `lazy-github debug` prints and Open Bug Report puts
  in the issue, with no selection left behind. `ctrl+c` in the modal does nothing, as before any copy in Python.
- Rows: `modals.debug-modal-contents`

Copy to Clipboard selects all of the `Markdown` widget's text and copies the selection, so the clipboard gets the
rendered text: the headings without `#`, the list items as `•  LazyGithub Version: 0.6.6`, no blank line between
the last list item and the "LazyGithub Config" heading, and the config without its code fence. Pasted into a GitHub
issue, which is where the modal's text is meant to go, the headings and the code block are lost and the JSON
renders as one paragraph. The selection stays after the copy, so the whole text is drawn highlighted until the modal
closes, and `ctrl+c` (Textual's `screen.copy_text`) copies it again without a toast. Before the first copy there's
no selection and `ctrl+c` copies nothing.

The Rust markdown renderer has no text selection, so reproducing this would mean building one for this button.
Found while designing the Debug Info modal (#195, #312), in a Textual pilot run of `DebugModal`. #312's
spec follows the answer.
