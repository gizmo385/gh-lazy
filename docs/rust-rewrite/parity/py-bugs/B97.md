# B97: `clear-config` and `clear-cache` crash with a traceback when the delete fails

- Id: B97
- Status: answered
- Answer: Follow the recommendation. (Chris, 2026-10-28, [comment](https://github.com/gizmo385/gh-lazy/issues/309#issuecomment-6485043174))
- Python reference: `cli.py` `clear_config` (`Path.unlink(missing_ok=True)`), `clear_cache` (`shutil.rmtree`)
- Recommendation: Print one line on stderr, `Error: failed to delete <path>: <reason>`, and exit 1, as the
  broken-config error does (decision `broken-config-error`). Nothing else changes: the success and cancel messages,
  and a missing file or folder counting as cleared, stay as they are.
- Rows: `cli.clear-config`, `cli.clear-cache`

Both commands delete without catching errors. `clear-config` crashes with a Python traceback when `config.json`
can't be removed (it's a directory, or its folder isn't writable), and `clear-cache` does when `cache_directory`
names a file rather than a folder (`NotADirectoryError`) or something inside can't be removed. The exit code is 1
and the user gets a traceback instead of a sentence.

Found while designing the CLI subcommands (#199). #309's spec follows the answer.
