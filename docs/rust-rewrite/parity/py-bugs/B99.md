# B99: Link hints label links that aren't on screen

- Id: B99
- Status: open
- Answer:
- Python reference: `ui/widgets/link_hints.py` `collect_link_hits` (uses `Widget.region` and `content_region`,
  which come from Textual 8.2.5's compositor full map, unclipped and unscrolled), `LinkHintScreen.compose`
- Recommendation: Label only the links drawn on screen, in their pane's visible area. Labels are assigned among those
  only, and none is drawn over other UI (#340).
- Rows: `markdown-links.hint-labels`

`collect_link_hits` walks every displayed widget on the main screen and takes each link's position from the widget's
region in Textual's full compositor map, which isn't clipped to the scrolling container's viewport. It stops only at
the widget's own bottom edge. So every link in a long README, PR body or comment list gets a label, including the
ones scrolled out of view above or below.

What the user sees, reproduced under the parity harness (#196's design probe: a README with 40 links at 160x48):

- Links scrolled out of view still take letters in the sequence, so the links that are visible can get two-letter
  labels, or later letters, even when only a handful are on screen.
- Labels for links below the view are drawn wherever their unscrolled position lands: over the Details pane's bottom
  border ("ay") and over the footer ("P NeauPR", "f Follow linkaiF"). Labels for links above the view, or past the
  bottom of the screen, aren't drawn at all, but can still be typed blind.

The Rust `LinkMap` (#339) records links as they're drawn, so labelling only visible links is also the natural
implementation. Copying Python would need positions for content that isn't drawn.
